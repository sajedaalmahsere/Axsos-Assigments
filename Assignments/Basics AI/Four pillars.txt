# The Four Pillars of OOP in Python

The four main pillars are:

1. **Abstraction** → Hide unnecessary details
2. **Encapsulation** → Keep data and behavior together and control access
3. **Inheritance** → Create a new class from an existing class
4. **Polymorphism** → The same method/action can behave differently for different objects

---

## 1. Abstraction

### Simple explanation

**Abstraction means hiding the complicated details and showing only what the user needs.**

Think about a car:

You use:

```text
car.start()
```

You don't need to know everything happening inside the engine.

In programming, abstraction allows us to use something without worrying about how everything inside it works.

### Python example

```python
class Car:
    def start(self):
        print("Car is starting...")


car = Car()
car.start()
```

### How does this demonstrate abstraction?

We only need to call:

```python
car.start()
```

We don't need to know how the car's starting process works internally.

The `start()` method hides those details from the person using the object.

### Output

```text
Car is starting...
```

### Beginner idea

> **Abstraction = "I use it without needing to know all the details behind it."**

---

# 2. Encapsulation

### Simple explanation

**Encapsulation means keeping data and the methods that work with that data together inside a class.**

It can also mean controlling how the object's data is accessed or changed.

For example, imagine a bank account.

You don't want other code to freely change the balance.

### Python example

```python
class BankAccount:
    def __init__(self, balance):
        self.__balance = balance

    def deposit(self, amount):
        self.__balance += amount

    def show_balance(self):
        print(self.__balance)


account = BankAccount(100)
account.deposit(50)
account.show_balance()
```

### How does this demonstrate encapsulation?

The balance is stored inside the object:

```python
self.__balance
```

The `__` tells Python that this attribute is intended to be **private**.

Instead of changing the balance directly, we use a method:

```python
account.deposit(50)
```

So the class controls how the balance is changed.

### Output

```text
150
```

### Important Python note

Python's approach to encapsulation is different from languages such as Java.

Python does not strongly enforce private attributes in the same way. The `__` syntax provides a mechanism for name mangling, but Python generally follows the idea:

> "We're all consenting adults here."

So Python programmers often use conventions such as:

```python
_balance
```

to indicate:

> "This is internal. Please don't access it directly."

### Beginner idea

> **Encapsulation = "Keep data and the methods that control that data together."**

# 3. Inheritance

This is probably one of the most important pillars in your Python course.

### Simple explanation

**Inheritance allows one class to get attributes and methods from another class.**

For example:

```text
Animal
   ↓
Dog
```

A `Dog` is an `Animal`, so the `Dog` can inherit things from `Animal`.

### Python example

```python
class Animal:
    def eat(self):
        print("Animal is eating")


class Dog(Animal):
    def bark(self):
        print("Dog is barking")


dog = Dog()

dog.eat()
dog.bark()
```

### How does this demonstrate inheritance?

We created:

```python
class Dog(Animal):
```

This means `Dog` inherits from `Animal`.

Therefore, the `Dog` object can use:

```python
dog.eat()
```

even though `eat()` was written inside the `Animal` class.

It can also use its own method:

```python
dog.bark()
```

### Output

```text
Animal is eating
Dog is barking
```

### Beginner idea

> **Inheritance = "A child class can reuse things from a parent class."**

You will often see these terms:

```text
Parent class → Child class
Base class   → Derived class
Super class  → Subclass
```

They are referring to the same general relationship.

# 4. Polymorphism

### Simple explanation

**Polymorphism means "many forms."**

In OOP, different objects can have a method with the **same name**, but each object can perform the action differently.

For example:

```text
Dog → speak() → Woof
Cat → speak() → Meow
```

Both have:

```python
speak()
```

but they behave differently.

### Python example

```python
class Dog:
    def speak(self):
        print("Woof")


class Cat:
    def speak(self):
        print("Meow")


dog = Dog()
cat = Cat()

dog.speak()
cat.speak()
```

### How does this demonstrate polymorphism?

Both objects use the same method name:

```python
speak()
```

But:

```python
dog.speak()
```

produces:

```text
Woof
```

while:

```python
cat.speak()
```

produces:

```text
Meow
```

The same action:

```python
speak()
```

has different behavior depending on the object.

### Output

```text
Woof
Meow
```

### Beginner idea

> **Polymorphism = "Same method/action, different behavior."**

| **Encapsulation** | Keep/control data inside the class | "Protect and control the data."      |

# Why does your Python course focus more on Inheritance and Polymorphism?

This makes sense because **inheritance and polymorphism are very closely connected**.

For example:

```python
class Animal:
    def speak(self):
        print("Animal sound")


class Dog(Animal):
    def speak(self):
        print("Woof")


class Cat(Animal):
    def speak(self):
        print("Meow")
```

Here we have both:

**Inheritance:**

```python
Dog(Animal)
Cat(Animal)
```

The `Dog` and `Cat` inherit from `Animal`.

And **polymorphism:**

```python
dog.speak()
cat.speak()
```

Both classes have `speak()`, but they behave differently.

So when you're learning inheritance, you naturally encounter **method overriding and polymorphism**.

# Why isn't Encapsulation taught exactly like in Java or other languages?

This is an important difference between Python and some other OOP languages.

In languages such as Java, you commonly see:

```java
private
public
protected
```

These access modifiers are an important part of controlling access to class members.

Python takes a more flexible approach.

For example:

```python
class Student:
    def __init__(self):
        self.name = "Sajeda"
        self._grade = 90
```

The underscore:

```python
_grade
```

is mainly a **convention** telling other programmers:

> "This is intended to be used internally."

Python doesn't try to prevent programmers from accessing it as strictly as some languages do.

Python also has:

```python
__balance
```

which uses **name mangling**, giving stronger protection from accidental direct access, but it is still not the same access-control system you might see in Java.

So encapsulation **does exist in Python**, but it looks different.

# Why can OOP pillars look different in Python?

The four pillars are **general OOP ideas**, not four identical pieces of syntax that every language must implement in exactly the same way.

Different programming languages have different philosophies.

For example:

### Java

Often emphasizes:

```text
public
private
protected
interfaces
abstract classes
```

### Python

Often emphasizes:

```text
simple syntax
conventions
duck typing
flexibility
classes and inheritance
```

So the **idea** can be the same while the **implementation** is different.

For example:

**Encapsulation**

```text
Java → private fields + getters/setters
Python → conventions + properties/name mangling
```

**Abstraction**

```text
Java → interfaces / abstract classes
Python → can use simpler class/method designs, and also supports abstract classes
```

**Polymorphism**

```text
Java → often through inheritance/interfaces
Python → can be very flexible because objects can be used based on what methods they provide
```
